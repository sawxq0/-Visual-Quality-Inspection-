# Отчет по лабораторной работе № 3
## Реализация программного компонента системы искусственного интеллекта

**1. Тема проекта и реализованный компонент**
* **Тема проекта:** Система визуального контроля качества продукции (Visual Quality Inspection), кейс №7 (Дефектоскопия продукции на конвейере).
* **Реализованный компонент:** Оркестрация бизнес-правил и инференс (`app.service.QualityInspectionService`). Компонент принимает данные, проверяет их, выполняет интеллектуальную функцию и возвращает типизированный результат.

**2. Место на архитектурной схеме из ЛР № 2**
В компонентной диаграмме ЛР № 2 (C4 Model, Level 2) реализованный компонент занимает место блока «Прикладные бизнес-правила» и связывает между собой модули «Feature Preprocessing» (подготовка изображения) и «Model Inference Engine» (вызов модели). Компонент изолирован от веб-сервера (FastAPI) и представляет собой чистый Python-код.

**3. Входной и выходной контракт**
* **Вход (PredictionRequest):** 
  * `item_id` (строка) — идентификатор изделия.
  * `image_base64` (строка) — изображение в формате base64.
  * `camera_id` (строка) — идентификатор камеры.
* **Выход (PredictionResult):** 
  * `request_id` (UUID) — уникальный идентификатор запроса.
  * `item_id` (строка) — идентификатор изделия.
  * `prediction` (enum) — вердикт (DEFECT / NORMAL).
  * `confidence` (float) — уверенность модели от 0.0 до 1.0.
  * `model_version` (строка) — версия модели (1.0.0).
  * `manual_review_required` (bool) — флаг необходимости ручной проверки.
* **Ошибки:** `InvalidInputError` (при битом base64), `ModelInferenceError` (при сбое нейросети).

**4. Используемая модель/алгоритм и источник тестовых данных**
* **Модель/алгоритм:** Нейросеть MobileNetV3 (библиотека `torchvision`), предобученная на ImageNet. Последний слой заменен на классификатор из 2 классов (DEFECT / NORMAL). Используется честный инференс на PyTorch (CPU). 
* **Прикладное правило:** Если `confidence < 0.75`, компонент выставляет флаг `manual_review_required = True` (согласно FR-03 из ЛР2).
* **Источник тестовых данных:** Тестовые изображения генерируются «на лету» в самих тестах с помощью библиотеки `Pillow` (создается черный квадрат 100x100, кодируется в base64). Это исключает необходимость хранить личные данные или большие файлы в репозитории.

**7. Ограничения компонента и ожидаемое развитие**

* **Ограничения:** В рамках 4 часов лабораторной работы модель MobileNetV3 не дообучалась на реальном датасете царапин и сколов. Она используется как baseline для демонстрации полного и честного пайплайна инференса. На случайных картинках она может выдавать случайные результаты. Кроме того, компонент пока не сохраняет маски дефектов (возвращает `defect_mask_url=None`).
* **Ожидаемое развитие:** В следующих лабораторных работах планируется обернуть этот изолированный компонент в REST API (FastAPI), добавить Docker-контейнеризацию, настроить CI/CD и, при наличии данных, дообучить модель (fine-tuning) на реальных изображениях конвейера.
